# Welcome To My Automated HTML/CSS Resume Pipeline

This repo features an automated CI/CD pipeline that syncs structural resume data from a either a cloud-managed or DOCX Google Doc, transforms it semantically using Pandoc, compiles a web layout with a custom CSS engine, and deploys it automatically to GitHub Pages.

Live Deployment: [glaring-seagull.github.io/HTML-Resume](https://glaring-seagull.github.io/HTML-Resume)

---

## Architecture Overview

The system eliminates manual data reentry by decoupling raw content management from visual presentation layouts. 

1. **Content Control Layer:** Content edits are performed natively inside a shared Google Doc workspace.
2. **Orchestration Runner (GitHub Actions):** A secure automated runner triggers via cron schedules or manual dispatches.
3. **Authentication Layer:** The runner assumes a Google Cloud Platform (GCP) IAM Service Account identity via encrypted RSA private key JSON blocks.
4. **Processing Pipeline:** The Python core invokes the Google Drive v3 API (`export_media` or `get_media`), runs a custom regex sanitization filter to clean up document artifacts, and uses Pandoc to compile a clean HTML tree.
5. **Git Ops Lifecycle:** If modifications are identified in the compiled assets, the runner isolates changes in an automated branch and opens a Pull Request for review.

## Setup & Configuration

To replicate this automation workspace in your own repository, ensure the following specifications are met:

### 1. Repository Secrets
Navigate to `Settings -> Secrets and variables -> Actions` and populate the following protected keys:
* `GOOGLE_SERVICE_ACCOUNT_JSON`: The flat, un-nested JSON private key file generated from your Google Cloud IAM Console under the `Keys` tab.
* `GOOGLE_DOC_FILE_ID`: The distinct resource identifier extracted directly from your Google Doc browser navigation bar (`https://docs.google.com/document/d/[THIS_ID]/edit`).

### 2. Workspace Access Controls
Your automated GCP identity requires standard reader scoping to parse document models. 
* Open your target Google Doc.
* Click **Share**.
* Provision **Viewer** privileges directly to the `client_email` address declared inside your service account credentials file.

## Development & Automation Tuning

### Triggering the Runner
The workflow is engineered to execute automatically on a cron schedule (`0 0 1 * *` - monthly intervals) to continuously sync with google drive hosted resume. 

To execute an immediate build manually:
1. Navigate to the **Actions** tab inside your repository dashboard.
2. Select **Automated Resume Generation** from the sidebar workflow index.
3. Click the **Run workflow** dropdown interface and initiate execution on your target development branch.

### Modifying Layout Aesthetics
Visual styles are decoupled entirely from the build logic. To adjust typography hierarchies, container responsive scales ($48\text{rem}$ limits), color tokens, or print sheet targets, modify `docs/main.css` directly. The compilation engine safely builds layout variations over consecutive runs. 

Note that this was designed around how I formatted my own resume, it will likely require some rework in the `HTML Sanitization and Class Injection` block to get it working for your own!
